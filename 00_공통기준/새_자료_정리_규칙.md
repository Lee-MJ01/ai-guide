# 새 자료 정리 규칙

> 요약: 새 링크·영상·PDF·노션을 이 가이드에 넣을 때의 파일 형식, 위치, 인덱스 갱신 순서. | 언제: "이거 정리해 줘", "가이드에 추가해 줘" | 갱신: 2026-11-20

## 0. 먼저

- 파일을 만들거나 고치기 전에 `00_공통기준/저장소_운영_규칙.md`를 따른다(pull → 수정 → 인덱스 → 커밋 → push).
- 글(md)은 GitHub 저장소에, PDF·zip·이미지 같은 원본 자료는 `[Drive]` 같은 폴더 경로에 둔다. 원본 자료를 Drive에 올리면 GitHub 쪽 폴더 `index.md`에 `[Drive]/경로`로 한 줄을 남긴다.

## 1. 어디에 둘까

1. 루트 `index.md`의 폴더 목차에서 가장 가까운 폴더를 고른다.
2. 맞는 폴더가 없고 같은 주제 자료가 2개 이상 쌓일 것 같으면 새 폴더를 만든다. 이름은 `NN_주제`(번호는 다음 번호).
3. 한 폴더에 문서가 8개를 넘으면 하위 폴더로 나누고, 하위 폴더에도 `index.md`를 만든다.
4. 스킬·플러그인 소개 자료는 주제와 상관없이 `06_스킬_플러그인/`에 두고, 주제 폴더 `index.md`에는 링크만 건다.

## 2. 파일 이름

- 가이드(반복 작업 절차): `주제_가이드.md`
- 자료 정리(영상·게시물·글): `주제_핵심어.md`. 날짜가 중요하면 앞에 `YYYY-MM-DD_`.
- 파일 이름에 `\ / : * ? " < > |` 를 쓰지 않는다.

## 3. 문서 첫머리 (꼭 지킨다 · AI가 이 두 줄만 보고 판단함)

```markdown
# 제목

> 요약: 한두 문장 | 언제: 이런 요청일 때 | 키워드: a, b, c | 관련 스킬: 이름 | 출처: 링크 | 갱신: YYYY-MM-DD
```

## 4. 본문 구성

- **가이드형:** 목적 → 절차(번호) → 출력 형식 → 실행 명령 예시 → 주의점
- **자료형(영상·게시물):** 정보 → 핵심 요약 → 바로 써먹을 것 → 주장과 확인할 점 → 분석 한계 → 출처
- 남의 글·프롬프트는 통째로 옮기지 않는다. 내 말로 구조를 요약하고 원문 링크를 남긴다.
- 비밀번호·API 키는 md에 쓰지 않는다.

## 5. 인덱스 갱신 (같은 작업 안에서)

1. 해당 폴더 `index.md` 표에 한 줄 추가
2. 새 폴더를 만들었으면 루트 `index.md`의 "폴더 목차"와 "요청별 빠른 길"에 추가
3. 스킬·플러그인이면 `06_스킬_플러그인/스킬_플러그인_레지스트리.md`에 한 줄 추가
