# 저장소 운영 규칙 (GitHub ↔ Google Drive)

> 요약: 이 가이드를 고치거나 자료를 추가하는 모든 AI가 지켜야 하는 규칙. 무엇을 어디에 두는지, 읽기 전·쓰기 전·끝내기 전에 할 일, 충돌 처리, 금지 사항. | 언제: 가이드 문서를 하나라도 만들거나 고치거나 옮기기 전에 반드시 | 키워드: git, 동기화, 충돌, Drive, 원본 | 갱신: 2026-11-20

사용자는 이 저장소를 거의 직접 고치지 않는다. **고치는 쪽은 항상 AI**이고, 여러 PC·여러 AI가 번갈아 작업한다. 그래서 아래 규칙은 "다른 AI가 방금 무언가를 바꿨을 수 있다"는 전제로 쓰였다. 규칙이 애매하면 더 보수적인 쪽(덮어쓰지 않는 쪽)을 고른다.

---

## 1. 원본은 한 곳뿐 (가장 중요)

| 종류 | 원본 위치 | 다른 곳에 두면 안 되는 이유 |
| --- | --- | --- |
| 글 파일: `.md`, 스킬 `SKILL.md`, 설정 JSON, 설치 스크립트(`.cmd` `.ps1` `.sh`) | **GitHub** `Lee-MJ01/ai-guide` | 두 곳에서 고치면 어느 쪽이 최신인지 알 수 없다 |
| 큰 파일: PDF, zip, 이미지, 영상, 오디오, 1MB 넘는 파일 | **Google Drive** `내 드라이브/AI_공통_작업_가이드/` (이하 `[Drive]`) | git 이력에 영원히 남아 저장소가 계속 커진다 |
| 비밀 정보: API 키, 비밀번호, 토큰, `freellmapi-sync.json` | **Drive** `[Drive]/05_LLM다루기/FreeLLMAPI-Sync/` | GitHub에 한 번 올라가면 지워도 이력에 남는다 |
| 개인 정보 글: 사용자 경력·프로젝트명·자격·연락처 등 | **Drive** `[Drive]/_개인/` (현재 `사용자_배경.md`, `취업/`) | **이 저장소는 공개(public)다.** 누구나 읽을 수 있다 |
| 스킬 실행용 Drive 파일: `[Drive]/tools/pdf_ingest.py`, `[Drive]/_pdf_cache/`, `[Drive]/05_LLM다루기/FreeLLMAPI-Sync/freellmapi-kit/` | **Drive** | 계정 스킬(pdf-drive-analyzer, freellmapi)이 Drive 경로에서 직접 읽는다. 옮기면 스킬이 깨진다 |
| 내가 만든 스킬의 실제 동작본 | **claude.ai 계정** (Claude 앱·Claude Code에 자동 동기화) | GitHub `plugins/my-skills/`는 그 원문 사본이다. 6장 참고 |

- `[Drive]` 표기는 `G:\내 드라이브\AI_공통_작업_가이드\`(Windows) 또는 `~/Library/CloudStorage/GoogleDrive-*/내 드라이브/AI_공통_작업_가이드/`(macOS)를 뜻한다.
- Drive에 남아 있는 옛 `.md` 파일은 모두 "GitHub로 이사함" 안내문이다. **Drive의 md를 읽거나 고치지 않는다.** 안내문의 GitHub 경로로 간다. 예외는 `[Drive]/_개인/` 아래 비공개 문서뿐이다.
- Drive 폴더 이름(`AI_공통_작업_가이드`)과 위 실행용 경로는 바꾸지 않는다(스킬이 이 경로를 쓴다).

## 2. 가이드에 접근하는 방법 (환경별)

| 환경 | 읽기 | 쓰기 |
| --- | --- | --- |
| Claude Code (PC) | 로컬 클론 `~/ai-guide` (Windows `%USERPROFILE%\ai-guide`). 없으면 3장대로 클론 | 가능 |
| Claude Code 클라우드 세션·원격 세션 | 세션에 저장소를 붙이고 얕게 클론 | 가능 |
| Codex·Cursor 등 git이 되는 에이전트 | 로컬 클론 | 가능 (같은 규칙) |
| Claude 앱 일반 채팅 (git 없음) | 공개 저장소라 `https://raw.githubusercontent.com/Lee-MJ01/ai-guide/master/<경로>`로 바로 읽힌다(웹 가져오기). 한글 경로는 URL 인코딩 | **불가.** 바꿀 내용을 사용자에게 보여 주고 "git이 되는 환경에서 반영하겠다"고 알린다. Drive에 md를 대신 쓰지 않는다 |

- 로컬 클론 위치는 **Google Drive·OneDrive·Dropbox 같은 동기화 폴더 밖**이어야 한다. 동기화 프로그램이 `.git` 폴더를 건드려 저장소가 깨진다.
- 저장소는 글 파일만 있어서 1MB 안팎이다. 용량이 작은 노트북에도 받아도 된다.

## 3. 읽기 전에 (매번)

1. 클론이 없으면: `git clone --depth 1 https://github.com/Lee-MJ01/ai-guide.git ~/ai-guide`
2. 클론이 있으면: `git -C ~/ai-guide pull --ff-only`
   - 실패하면(로컬에 안 올린 커밋이 있음): 5장 충돌 처리로 간다. 그냥 읽기만 할 거면 `git -C ~/ai-guide status`로 상태를 사용자에게 알리고 읽기는 계속한다.
3. `index.md` → 폴더 `index.md` → 문서 1~2개 순서로 읽는다(루트 `index.md` 0장).

## 4. 쓰기 (만들기·고치기·옮기기·지우기)

**작업 시작 시**
1. `git pull --ff-only`로 최신 상태를 받는다. 받기 전에 파일을 고치지 않는다.
2. `git status`가 깨끗한지 본다. 내가 만들지 않은 변경이 남아 있으면 손대지 않고 사용자에게 알린다(다른 AI의 미완료 작업일 수 있다).

**작업 중**
3. 한 번에 한 주제만 바꾼다. 관련 없는 파일의 줄바꿈·공백·형식을 함께 고치지 않는다.
4. 파일을 고칠 때는 해당 부분만 바꾼다. 파일 전체를 다시 쓰는 것은 새 파일이거나 사용자가 요청한 경우만.
5. 문서 첫머리 형식과 인덱스 갱신은 `00_공통기준/새_자료_정리_규칙.md`를 따른다. **문서를 추가·이름변경·삭제하면 같은 커밋 안에서** 해당 폴더 `index.md`(필요하면 루트 `index.md`)도 고친다.
6. 큰 파일이 필요하면 Drive에 올리고, GitHub 쪽 폴더 `index.md`에 `[Drive]/경로` 한 줄을 추가한다. 큰 파일 자체는 커밋하지 않는다.
7. 파일을 옮기거나 이름을 바꿀 때는 `git mv`를 쓰고, 그 파일을 가리키던 링크를 `git grep "옛이름"`으로 찾아 모두 고친다.
8. 삭제는 사용자가 요청했을 때만. 오래된 자료는 지우지 말고 문서 첫머리에 `> 상태: 보관(사용 안 함) · 대체: <새 문서>`를 붙인다.

**작업 끝**
9. 커밋 전 점검:
   - `git status`로 의도한 파일만 바뀌었는지 확인
   - `git diff --cached --stat`로 큰 파일·비밀 파일이 없는지 확인 (7장 금지 목록)
   - 인덱스에 새 문서가 들어갔는지 확인
10. 커밋 메시지 형식: `<분류>: <무엇을> (<어느 PC/환경>)`
    - 분류: `add`(새 문서), `update`(내용 수정), `move`(이동·이름변경), `index`(인덱스만), `skill`(스킬), `record`(설치 현황 기록), `rule`(규칙 변경)
    - 예: `add: korean-skills 휴머나이저 정리 (desktop-ntuj7e4 / Claude 앱)`
11. **바로 push한다.** 커밋만 하고 끝내지 않는다. `git push`가 거절되면 5장.
12. 사용자에게 "무엇을 어디에 반영했는지"를 한두 줄로 알린다.

## 5. 충돌·실패 처리

| 상황 | 할 일 |
| --- | --- |
| `pull --ff-only` 실패 (내 쪽에 안 올린 커밋 있음) | `git pull --rebase` → 충돌 없으면 push |
| rebase 중 충돌 | 두 내용을 모두 살려 합친다. 한쪽을 버려야 하면 **멈추고** 두 버전을 사용자에게 보여 준 뒤 고르게 한다 |
| 인덱스 표(`index.md`)에서 충돌 | 양쪽 줄을 모두 남긴다(대부분 서로 다른 문서를 추가한 경우) |
| push 거절 (원격이 앞서감) | `git pull --rebase` 후 다시 push. 두 번 실패하면 멈추고 알린다 |
| 네트워크 안 됨 | 로컬 커밋까지만 하고, 사용자에게 "push 안 됨, 다음 작업 때 올림"이라고 알린다. 다음 작업의 3장 1단계에서 먼저 push |
| 이유를 모르는 이상한 상태 | 아무것도 지우거나 되돌리지 말고 `git status`, `git log --oneline -5` 결과를 사용자에게 보여 준다 |

**절대 하지 않는 것:** `git push --force`, `git reset --hard`, `git clean -fd`, `git checkout -- .`, 히스토리 다시 쓰기, 브랜치 삭제. 사용자가 명시적으로 요청한 경우만 예외.

## 6. 스킬 원문 관리 (`plugins/my-skills/`)

- 실제 동작본은 claude.ai 계정의 스킬이다. GitHub `plugins/my-skills/skills/<이름>/SKILL.md`는 원문 사본 겸 이력 보관용이다.
- **스킬을 고칠 때 (둘 다 같은 작업 안에서):**
  1. GitHub의 `SKILL.md`를 고친다.
  2. Claude 앱에서 스킬 업데이트를 제안해(`propose_skills`) 계정 스킬에 반영한다. 반영할 수 없는 환경이면 사용자에게 "계정 스킬 반영 필요"라고 알리고 `_정리대기.md`에 적는다.
  3. `plugins/my-skills/.claude-plugin/plugin.json`과 `.claude-plugin/marketplace.json`의 `version`을 올린다(수정 1.0.0→1.0.1, 스킬 추가 1.0.0→1.1.0).
- 계정에서 먼저 고쳐졌다면(사용자가 Claude 앱에서 수정) 다음 작업 때 계정 내용을 GitHub 사본에 복사해 맞춘다.
- 새 스킬을 만들면 `plugins/my-skills/skills/<이름>/SKILL.md`를 추가하고 `06_스킬_플러그인/스킬_플러그인_레지스트리.md` A 표에 한 줄 추가.
- **중복 주의:** 계정 동기화가 되는 Claude Code에서는 이 마켓플레이스 플러그인을 설치하지 않는다(같은 스킬이 두 번 로드되어 토큰 낭비). 설치는 계정 동기화가 안 되는 환경(다른 계정, Codex 등)에서만.

## 7. 커밋 금지 목록

- 비밀: `*.env`, `*secret*`, `*token*`, `*credential*`, `freellmapi-sync.json`, `freellmapi.config.json`, `.env*`, API 키·비밀번호가 들어간 모든 파일 (`.gitignore`에 등록돼 있지만 이름이 다를 수 있으니 내용으로도 확인)
- 큰 파일: `*.pdf`, `*.zip`, `*.png`, `*.jpg`, `*.mp4`, `*.mov`, `*.mp3`, 1MB 넘는 파일
- Drive 전용: `_pdf_cache/`, `*.gdoc`, `*.gsheet`
- 기기 고유 파일: `*.log`, `.DS_Store`, `Thumbs.db`, `desktop.ini`
- 개인 정보: 이력서 원본, 연락처, 실명과 함께 쓰인 경력 상세, `[Drive]/_개인/`의 내용. **저장소가 공개라서** 경력·프로젝트명·자격은 GitHub 문서에 적지 않고 `[Drive]/_개인/사용자_배경.md`를 가리키기만 한다.
- 다른 사람의 글·프롬프트 원문 전체 (요약과 링크만)

## 8. PC별 기록

- 플러그인·MCP 서버를 설치하거나 지우면 `06_스킬_플러그인/컴퓨터별_설치현황.md`를 고치고 `record:` 커밋으로 push한다.
- PC 이름은 `hostname`(Windows) 결과를 쓴다.

## 9. 이 규칙을 바꿀 때

- 사용자가 요청했을 때만 바꾼다. 커밋 분류는 `rule:`.
- 규칙을 바꾸면 루트 `CLAUDE.md`·`AGENTS.md`의 요약도 같이 맞춘다.
