# 디자인 시스템 원샷 프롬프트 · 구조와 검수 기준

> 요약: 일반 Frame과 하드코딩 값으로 된 MVP 화면을 "토큰 → Variables·Styles → Components → Instance 재구성 → 가이드 문서 → 제작 규칙" 순서로 한 번에 바꾸게 하는 프롬프트의 단계별 요구사항 요약. | 언제: 원샷 프롬프트 실행 전 이해, 실행 후 결과 검수, 비슷한 프롬프트를 직접 쓸 때 | 출처: https://app.notion.com/p/AI-41c4639f584f81e5b9f5df629eb9053a | 갱신: 2026-11-20

> 프롬프트 원문은 위 출처 페이지의 회색 상자에서 복사한다. 이 문서는 원문을 옮기지 않고 무엇을 요구하는지만 정리했다.
> AI가 원문이 필요하면 내장 브라우저로 출처 페이지를 연다(이 노션은 남의 워크스페이스라 Notion 커넥터로는 안 열림).

## 전제 (프롬프트 머리)

- 역할: 시니어 프로덕트 디자이너 겸 디자인 시스템 담당
- 구조·네이밍·속성 이름·문서 형식은 원티드 디자인 시스템 규칙을 따르되, 원티드 브랜드 요소는 복제하지 않고 내 MVP의 서비스명·색·무드를 유지
- 화면에 없는 기능·화면은 새로 만들지 않음

## 완료 보고 (프롬프트가 요구하는 체크리스트)

- 원티드 구조 페이지 구성 · Atomic/Semantic 컬렉션 + Light/Dark
- Text·Effect Style 등록 · 공통+전용 Component Set, 모든 속성이 Instance 패널에서 제어
- Button(State·Disable), Textfield(State·Status·Disable), Bottom Nav(Active Tab) 동작
- Screens v2가 Instance + Auto Layout만으로 구성(하드코딩 0, Detach 0)
- Overview·Updates·Foundation·Guidelines 문서, Makers' Principle 기록
- 보고 형식: ① 0단계 결과 ② 컬렉션별 변수 개수 ③ 스타일 목록 ④ 컴포넌트·속성 목록 ⑤ 남은 이슈

## 이 프롬프트에서 배울 점 (다른 프롬프트를 쓸 때 재사용)

1. **분석을 먼저 보고하게 한다** (0단계) → AI가 내 화면을 모른 채 일반론으로 만드는 것을 막는다.
2. **원본 보존 규칙** (Archive 복제) → 되돌릴 수 있게.
3. **참고 체계를 이름으로 지정** (원티드 DS) → 네이밍·구조가 일관된다. 브랜드 복제 금지를 함께 적는다.
4. **완료 기준을 체크리스트로** → AI가 스스로 검사하고 남은 이슈를 보고한다.
5. **규칙을 결과물 안에 기록** (Makers' Principle) → 기억이 없는 AI도 다음 작업에서 규칙을 다시 읽을 수 있다. 이 가이드 폴더의 `index.md`와 같은 원리다.
