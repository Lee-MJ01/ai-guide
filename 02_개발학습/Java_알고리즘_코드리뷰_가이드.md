# Java 알고리즘 코드 리뷰 가이드

## 목적

정답 코드만 받는 것이 아니라, 현재 코드에서 사고가 어긋난 지점과 상태 변화를 이해하고 스스로 다시 풀 수 있게 한다.

## 리뷰 순서

1. 사용자의 풀이 의도를 먼저 한 문단으로 정리한다.
2. 잘한 점과 유지할 부분을 구체적으로 찾는다.
3. 컴파일 오류, 런타임 오류, 논리 오류를 구분한다.
4. 가장 먼저 잘못된 전제나 상태 정의를 지적한다.
5. 작은 예제로 변수와 자료구조의 변화를 추적한다.
6. 수정 방향을 설명한 뒤 사용자의 코드 스타일을 최대한 유지한 전체 코드를 제시한다.
7. 시간복잡도와 메모리복잡도, 자주 틀리는 경계 조건을 검토한다.

## 설명 방식

DFS, BFS, 백트래킹, DP는 반드시 다음 흐름으로 설명한다.

`현재 상태 → 가능한 선택 → 다음 상태 → 종료 조건 → 되돌리기/기록`

그리디 접근은 코드 작성 전에 작은 반례로 선택의 안전성을 검증한다. 구현이 지나치게 복잡해지면 상태 정의가 잘못되었는지 먼저 확인한다.

## 출력 형식

1. 현재 접근 요약
2. 잘한 점
3. 핵심 오류와 발생 이유
4. 작은 예제 실행 흐름
5. 수정 방향
6. 수정된 전체 Java 코드
7. 복잡도와 재발 방지 체크포인트

## 실행 명령 예시

> 문제와 내가 작성한 Java 코드를 첨부했어. 바로 다른 정답을 제시하지 말고 이 가이드 순서대로 내 접근을 분석한 뒤, 내 코드 기준으로 수정해줘.
