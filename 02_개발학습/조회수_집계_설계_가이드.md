# 조회수 집계 설계 가이드 (유튜브 방식 참고)

> 요약: 게시글·상품·영상 등 "상세 화면 조회수"를 유튜브처럼 공개 조회수 + 참여 조회수 2단계로 세는 설계와 바로 붙여 쓸 SQL·서버·프런트 코드. 중복 제거, 봇 제외, 미리보기 제외, 테스트 목록 포함 | 언제: "조회수 기능 만들어 줘", "조회수 중복 막기", "인기순·많이 본 순 정렬", 새 프로젝트에 조회수 붙일 때 | 키워드: 조회수, view count, hit, engaged view, 중복 조회, 봇 필터, INSERT IGNORE, Spring, MyBatis, Vue | 출처: https://support.google.com/youtube/answer/2991785 , https://support.google.com/youtube/answer/12220281 , https://techcrunch.com/2025/03/26/youtube-is-changing-how-youtube-shorts-views-are-counted | 갱신: 2026-11-27

## 1. 목적

"새로고침할 때마다 +1", "세션마다 +1" 같은 단순 조회수는 숫자가 쉽게 부풀고, 클릭만 많이 받은 글이 인기 글이 된다. 유튜브가 공개한 집계 원칙을 작은 서비스에 맞게 옮겨, **어느 프로젝트에든 같은 규칙과 같은 코드 뼈대로** 붙일 수 있게 정리한다.

## 2. 유튜브는 어떻게 세나 (2026-11 확인)

| 원칙 | 공식 설명 요지 | 출처 |
| --- | --- | --- |
| 공개 조회수 | 재생이 **시작되는 순간** 센다. 쇼츠는 2025-03부터, 일반 영상·라이브까지 2026년에 같은 방식 | answer/2991785, answer/12220281, TechCrunch 2025-03-26 |
| 참여 조회수 (engaged views) | 처음 몇 초를 넘겨 **계속 본** 횟수, 반복 재생 제외. 수익·자격 판단은 이쪽 | answer/12220281, answer/2991785 |
| 품질 낮은 재생 제외 | 여러 기기로 같은 영상 보기, 여러 창·탭에서 같은 영상 틀기를 예로 들며 버린다. 사람 아닌 프로그램 재생 제외 | answer/2991785 |
| 늦은 확정 | 검증하느라 느려지거나 멈춰 보이거나 나중에 조정될 수 있고, 확정에 며칠 걸릴 수 있음 | answer/2991785 |

## 3. 작은 서비스용 규칙 (기본값)

| 유튜브 | 이 가이드의 기본 규칙 | 바꿀 수 있는 값 |
| --- | --- | --- |
| 재생 시작 = 조회 | **상세 API 가 권한 확인을 통과해 정상 응답할 때** 1조회. 403·404 면 안 셈 | — |
| 여러 탭·기기 = 1회 | **같은 시청자 + 같은 대상 + 같은 시간 구간 = 1회.** 시청자 = 로그인 회원 ID(기기 달라도 한 사람), 비로그인은 세션 ID | 구간 길이 (기본 30분) |
| 다시 보기는 셈 | 구간이 바뀌면 다시 센다 | — |
| 프로그램 재생 제외 | User-Agent 없음, 봇·크롤러·스크립트 패턴, 브라우저 미리 가져오기(`Sec-Purpose: prefetch`) → 안 셈 | 패턴 목록 |
| (추가) 보기 아닌 읽기 | 홈 미리보기·수정 폼처럼 상세 API 를 다른 용도로 읽을 때 프런트가 `X-No-View: 1` → 안 셈 | 헤더 이름 |
| 참여 조회수 | 화면이 **보이는 동안의 시간**이 N초 쌓이면 프런트가 따로 알림 → 조회 기록 하나당 1회 | N (기본 10초) |
| 인기는 참여 기준 | "많이 본 순" = 참여 조회 → 공개 조회 → 최신 | — |
| 작성자 본인 | 프로젝트에서 결정 (사용자에게 묻는다) | 포함 / 제외 |
| 늦은 확정 | 즉시 반영. 조회 기록을 며칠 보관해 필요하면 재집계 | 보관 기간 (기본 7일) |

**시작 전에 사용자에게 물을 것 (3개만):** 작성자 본인 조회 포함 여부 · 구간 길이 · 참여 기준 시간. 나머지는 기본값으로 진행한다.

## 4. 절차

1. 대상 테이블 정하기 (조회수를 셀 상세 화면 목록).
2. DB: 기록 테이블 1개 + 대상마다 `hit`, `engaged_hit` 컬럼 (5절).
3. 서버: 시청자 판별 → 조회 서비스 → 상세 API 에서 호출 → 참여 API (6절).
4. 기존에 상세 조회 서비스가 조회수를 올리고 있었다면 그 코드를 **지우고 한 서비스로 모은다** (규칙이 흩어지지 않게).
5. 상세 API 를 "보기"가 아닌 용도로 부르는 곳(홈 미리보기, 수정 폼 채우기, 관리 화면)을 전부 찾아 `X-No-View` 를 붙인다. → `grep -rn "Api.get(" src`
6. 프런트: 상세 화면에 참여 타이머 연결, 목록에 조회수·"많이 본 순" (7절).
7. 테스트 (8절) → 실제 화면에서 새로고침·10초 머물기로 DB 값 확인.

## 5. DB (MySQL 8)

```sql
CREATE TABLE IF NOT EXISTS view_logs (
  log_id      BIGINT AUTO_INCREMENT PRIMARY KEY,
  target_type VARCHAR(10)  NOT NULL,           -- BOARD, PRODUCT ... (enum 이름)
  target_id   INT          NOT NULL,
  viewer_key  VARCHAR(80)  NOT NULL,           -- m:회원ID / s:세션ID
  slot_start  DATETIME     NOT NULL,           -- 구간 시작 (예: 10:30)
  viewed_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  engaged     TINYINT(1)   NOT NULL DEFAULT 0,
  UNIQUE KEY view_logs_once_uk (target_type, target_id, viewer_key, slot_start),
  INDEX view_logs_viewed_idx (viewed_at)
);
ALTER TABLE boards ADD COLUMN hit INT NOT NULL DEFAULT 0, ADD COLUMN engaged_hit INT NOT NULL DEFAULT 0;
```

- **핵심은 UNIQUE + `INSERT IGNORE`.** "이미 봤나 조회 → 없으면 기록" 2단계로 하면 탭 여러 개를 동시에 열 때 경쟁 조건으로 2번 센다. `INSERT IGNORE` 의 영향 행 수(1/0)로 한 번에 판정한다.
- `target_id` 에는 FK 를 걸지 않는다(대상 테이블이 여러 개). 오래된 기록은 스케줄러로 지운다.
- 이미 `hit` 가 있는 테이블은 `engaged_hit` 만 추가.

## 6. 서버 (Spring Boot + MyBatis 예시)

**대상 enum** — SQL `${}` 에 들어갈 테이블·컬럼 이름은 enum 상수에서만 나오게 한다(사용자 입력 금지).

```java
public enum ViewTarget {
    BOARD("boards", "boards", "board_id"), PRODUCT("products", "products", "product_id");
    // path(URL 조각), table, idColumn + getter, static Optional<ViewTarget> fromPath(String)
}
```

**시청자** — 컨트롤러 파라미터로 받게 `HandlerMethodArgumentResolver` 를 하나 등록한다.

```java
public record Viewer(String key, boolean countable) {
    static final Pattern NON_HUMAN = Pattern.compile(
        "bot|crawl|spider|slurp|curl|wget|python|java/|okhttp|httpclient|headless|postman|scrapy", CASE_INSENSITIVE);
    public static Viewer from(HttpServletRequest req) {
        Member login = /* 세션의 로그인 회원 (세션을 새로 만들지 않고 getSession(false)) */;
        boolean human = isHuman(req);          // UA 패턴, Sec-Purpose/Purpose prefetch, X-No-View 확인
        if (login != null) return new Viewer("m:" + login.getUserId(), human);
        if (!human) return new Viewer("bot", false);   // 봇에게 세션을 만들어 주지 않는다
        return new Viewer("s:" + req.getSession(true).getId(), true);
    }
}
```

**매퍼 SQL**

```xml
<insert id="insertIgnore">
  INSERT IGNORE INTO view_logs (target_type, target_id, viewer_key, slot_start)
  VALUES (#{target}, #{targetId}, #{viewerKey}, #{slotStart})
</insert>
<update id="markEngaged">   <!-- 최근 구간 안의 기록 하나만 참여로 -->
  UPDATE view_logs SET engaged = 1
  WHERE target_type = #{target} AND target_id = #{targetId} AND viewer_key = #{viewerKey}
    AND viewed_at &gt;= #{since} AND engaged = 0
  ORDER BY viewed_at DESC LIMIT 1
</update>
<update id="increaseHit">UPDATE ${target.table} SET hit = hit + 1 WHERE ${target.idColumn} = #{targetId}</update>
<update id="increaseEngagedHit">UPDATE ${target.table} SET engaged_hit = engaged_hit + 1 WHERE ${target.idColumn} = #{targetId}</update>
<delete id="deleteBefore">DELETE FROM view_logs WHERE viewed_at &lt; #{before}</delete>
```

**서비스** (`@Transactional`)

```java
public boolean countView(ViewTarget t, int id, Viewer v) {
    if (v == null || !v.countable()) return false;
    if (mapper.insertIgnore(t, id, v.key(), slotStart(now())) == 0) return false; // 이 구간에 이미 셈
    mapper.increaseHit(t, id);
    return true;
}
public boolean countEngaged(ViewTarget t, int id, Viewer v) {
    if (v == null || !v.countable()) return false;
    if (mapper.markEngaged(t, id, v.key(), now().minus(SLOT)) == 0) return false;   // 조회 기록 없음·이미 참여
    mapper.increaseEngagedHit(t, id);
    return true;
}
@Scheduled(cron = "0 10 4 * * *") public void purge() { mapper.deleteBefore(now().minus(KEEP)); }
static LocalDateTime slotStart(LocalDateTime t) { /* 30분 단위 내림 : 10:47 → 10:30 */ }
```

- 생성자를 두 개(운영용 + 테스트용 `Clock` 주입) 두면 Spring 이 고르지 못해 **"No default constructor found"** 로 앱이 안 뜬다 → 운영용 생성자에 `@Autowired`.

**상세 API** — 권한 확인(서비스 조회)을 **먼저**, 센 뒤 응답 DTO 값도 +1.

```java
@GetMapping("/{id}")
public Board detail(@PathVariable int id, Viewer viewer) {
    Board b = boardService.get(id);                 // 여기서 403/404 가 나면 세지 않는다
    if (viewCountService.countView(ViewTarget.BOARD, id, viewer)) b.setHit(b.getHit() + 1);
    return b;
}
```

**참여 API** — `POST /api/views/{target}/{id}/engaged` → 셌든 안 셌든 204 (알 수 없는 target 은 404).

**정렬** — `sort=views` 일 때 `ORDER BY engaged_hit DESC, hit DESC, id DESC`. MyBatis 에서는 `<choose>` 로 값 분기, 정렬 컬럼을 `${}` 로 받지 않는다.

## 7. 프런트 (Vue 3 예시)

```js
// api : 보기 아닌 읽기용 설정
export const NO_VIEW = { headers: { 'X-No-View': '1' } };
// 상세 get 함수는 (id, config) 를 받게 바꾸고, 수정 폼·미리보기에서 get(id, NO_VIEW)

// composable : 보이는 시간만 모아 N초가 되면 한 번 알림
export function useEngagedView(target, id, ready) {
  let timer = null, visibleMs = 0;
  const stop = () => { clearInterval(timer); timer = null; };
  const start = (cur) => {
    stop(); visibleMs = 0;
    timer = setInterval(() => {
      if (document.visibilityState !== 'visible') return;   // 탭이 숨겨지면 시간 안 셈
      if ((visibleMs += 1000) >= 10_000) { stop(); viewsApi.engaged(target, cur).catch(() => {}); }
    }, 1000);
  };
  watch([id, ready], ([cur, ok]) => (ok && cur ? start(cur) : stop()), { immediate: true });
  onBeforeUnmount(stop);
}
// 상세 화면 : useEngagedView('boards', id, computed(() => post.value?.boardId === id.value))
```

- `ready` 는 "상세 내용을 받아 화면에 그린 뒤" 여야 한다 → 서버가 조회를 센 뒤에 참여가 오도록.
- 참여 알림 실패는 사용자에게 보여 주지 않는다(부가 기능).

## 8. 테스트 목록 (이것만 있으면 충분)

| 층 | 확인할 것 |
| --- | --- |
| 시청자 단위 | 회원 키 `m:`, 비회원 키 `s:`, 빈 UA·봇 UA·curl·python 은 countable=false 이고 세션도 안 만듦, prefetch·`X-No-View` 는 false |
| 서비스 (DB, 롤백) | 첫 조회 셈 / 같은 시청자 재조회 안 셈 / 다른 시청자 셈 / 봇 안 셈 / 참여는 조회 뒤에만, 한 번만 / 대상별 테이블에 반영 / 구간 내림 계산 |
| API (MockMvc) | 같은 세션 2번 열면 +1, 응답 hit 도 반영 / 403(비밀글·비공개) 이면 안 셈 / 참여 2번 보내도 +1 / 모르는 target 404 / `sort=views` 정상 |
| 프런트 (fake timers) | 10초 뒤 1회 / 숨김 동안 안 셈 / ready 전엔 시작 안 함 / id 바뀌면 처음부터 / 화면 떠나면 멈춤 |
| 실제 화면 | 새로고침 2번 → DB hit +1, 10초 머문 뒤 engaged_hit +1, 홈 미리보기만 보면 안 오름 |

- MockMvc 는 기본 User-Agent 가 없다 → 이 규칙에서는 **봇으로 판정**된다. 조회수를 기대하는 테스트는 `header("User-Agent", "Mozilla/5.0 ...")` 를 꼭 붙인다.

## 9. 주의점

- **고정 구간의 한계**: 10:29 → 10:31 새로고침은 구간이 달라 2회가 된다. 원자성(UNIQUE 키)을 얻는 대가로 받아들인다. 엄밀히 하려면 슬라이딩 윈도우 + 잠금이 필요하다.
- 세션 기반이라 비로그인 사용자가 브라우저를 바꾸면 다른 시청자다. 더 엄밀하게 하려면 IP+UA 해시를 보조 키로 쓰되 개인정보 보관 기간을 정한다.
- 대규모(초당 수천 조회)라면 DB 대신 Redis(`SET NX EX` 또는 HyperLogLog)로 중복을 막고 주기적으로 DB 에 합산한다.
- 상세 API 를 다른 화면이 재사용하는지 **반드시 grep** 한다. 홈 미리보기가 조회수를 올리는 실수가 가장 흔하다.
- 기존 "세션 Set" 방식이 있으면 남기지 말고 지운다. 규칙이 두 군데 있으면 언젠가 어긋난다.
