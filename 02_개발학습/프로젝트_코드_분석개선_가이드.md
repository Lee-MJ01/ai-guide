# 프로젝트·코드 분석 및 개선 가이드

## 목적

프로젝트를 단순 요약하지 않고, 백엔드 실무와 기술면접에서 설명할 수 있도록 코드 근거를 찾아 분석한다.

## 분석 원칙

- 저장소는 기본적으로 읽기 전용으로 분석하며, 변경 요청이 있을 때만 수정한다.
- README 설명보다 실제 코드, 설정, 스키마, 배포 파일을 우선 근거로 삼는다.
- 구현된 사실과 개선 아이디어를 구분한다.
- 보안, 트랜잭션, 동시성, 예외 처리, 권한, 성능, 운영 안정성을 함께 본다.

## 분석 항목

1. 프로젝트 목표와 사용자 문제
2. 전체 아키텍처와 데이터 흐름
3. 사용 기술과 선택 이유
4. 핵심 기능의 코드 실행 흐름
5. DB 모델과 트랜잭션 경계
6. 인증·인가와 보안 위험
7. 외부 API, 비동기 처리, 캐시, 배포·CI/CD
8. 테스트와 장애 대응 가능성
9. 잘한 설계와 기술 부채
10. 개선 우선순위와 예상 효과

## 면접 자료화

핵심 경험을 `문제 → 선택지 → 선택 이유 → 구현 → 검증 → 한계`로 정리하고 다음 질문을 만든다.

- 왜 이 기술을 선택했는가?
- 다른 방법과 비교했는가?
- 장애나 데이터 불일치가 발생하면 어떻게 되는가?
- 사용자 수가 늘면 어디가 먼저 병목이 되는가?
- 다시 만든다면 무엇을 바꿀 것인가?

## 출력 형식

- 한 페이지 프로젝트 요약
- 아키텍처·요청 흐름
- 코드 근거가 있는 강점
- 위험도별 개선 목록: 즉시 / 단기 / 장기
- 면접 질문과 답변 포인트
- 확인하지 못한 부분

## 실행 명령 예시

> 첨부한 저장소를 변경하지 말고 이 가이드에 따라 분석해줘. Java/Spring 백엔드 면접에서 설명할 수 있도록 코드 근거, 설계 판단, 개선점, 예상 질문을 정리해줘.
