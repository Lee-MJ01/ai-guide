# 에이전트는 하나만, 일마다 매뉴얼을 준다 (인터뷰 → 툴박스 → 검증)

> 요약: 일마다 에이전트를 새로 만들지 말고 에이전트 하나에 작업별 매뉴얼을 주라는 릴스 정리. 매뉴얼=스킬(SKILL.md), 툴박스=스킬 폴더의 스크립트·템플릿, 검증=완료 체크리스트로 바꿔 내 스킬 작업에 적용하는 법을 붙였다. | 언제: 새 에이전트·자동화를 만들려 할 때, 스킬을 새로 만들거나 고칠 때, 결과물 품질이 들쭉날쭉할 때 | 키워드: AI 에이전트 설계, 매뉴얼, 스킬, 툴박스, 검증, 완료 정의 | 관련 스킬: skill-creator, ai-guide-intake | 출처: https://www.instagram.com/p/DfzT6ecnYR3/ | 갱신: 2026-11-22

## 핵심 요약

메일용·보고서용·블로그용처럼 일마다 에이전트를 만들어 연결하면 반쯤 만든 프로젝트만 쌓이고 제대로 도는 건 몇 개 안 남는다. 잘 쓰는 사람은 **에이전트는 하나**로 두고 **일마다 매뉴얼**을 준다. 매뉴얼은 세 부분으로 만든다: AI가 질문으로 내 일을 뽑아내 정리한 매뉴얼, 한 번 만든 걸 모아 두는 툴박스 폴더, "완료"의 정의를 박아 둔 검증 목록. 결과가 틀리면 **채팅에서 고치지 말고 매뉴얼을 고친다** [0:35·1:12 화면].

## 세 단계 (캡션·화면 기준)

| 단계 | 내용 | 근거 |
| --- | --- | --- |
| ① 인터뷰 → 매뉴얼 | AI가 질문을 던져 내 업무 방식을 다 끌어내고, 그 답을 매뉴얼 문서로 정리 | 캡션, [0:30] 화면 |
| ② 툴박스 | 스크립트·템플릿·문서처럼 한 번 만든 것은 폴더에 쌓아 두고 다시 씀 | 캡션, [0:50] "만든 건 전부 여기 쌓인다" |
| ③ 검증 | 완료 조건을 목록으로 적어 두면 결과를 내기 전에 스스로 검사. 가장 많이 빠뜨리는 단계라고 강조 | 캡션, [1:00] "결과를 내기 전에 스스로 검사" |

## 바로 써먹을 것 (Claude 스킬로 옮기기)

이 방식은 Claude의 **스킬 구조와 그대로 겹친다.** 그래서 이 가이드에서는 새 에이전트를 만들지 않고 스킬을 만든다.

| 릴스의 말 | Claude에서 | 이 가이드에서 |
| --- | --- | --- |
| 에이전트 하나 | Claude (앱·Claude Code 공통, 계정 동기화) | — |
| 매뉴얼 | `SKILL.md` | `plugins/my-skills/skills/<이름>/SKILL.md` + 계정 스킬 |
| 툴박스 | 스킬 폴더의 `scripts/`·템플릿, 또는 Drive 실행 파일 | `[Drive]/tools/`, `scripts/` |
| 검증 | SKILL.md 끝의 "완료 체크리스트" | 각 가이드의 "출력 형식·주의점" |
| 매뉴얼을 고친다 | 스킬 수정(`propose_skills` edits) | `저장소_운영_규칙.md` 6장 |

**새 반복 작업이 생기면 (내가 쓰는 인터뷰 요청 예시, 원 게시물 프롬프트 아님)**
```
지금부터 내 [작업 이름] 방식을 스킬로 만들 거야. 한 번에 하나씩 질문해서
입력 자료, 순서, 판단 기준, 자주 하는 실수, 결과물 형식, '완료'의 조건을 다 뽑아 줘.
다 모이면 SKILL.md 초안(절차 + 템플릿 + 완료 체크리스트)으로 정리하고 스킬 저장 카드를 띄워 줘.
```

**결과가 틀렸을 때 습관**
1. 채팅에서 "다시 해 줘"로 끝내지 않는다.
2. 무엇이 빠졌는지 한 줄로 적고 → 해당 스킬의 절차나 체크리스트에 추가 → 스킬 업데이트.
3. 같은 실수가 두 번 나오면 체크리스트 항목으로 승격.

**검증 목록 예 (스킬 끝에 붙이는 형태)**
- [ ] 요청한 산출물 형식·위치가 맞는가
- [ ] 수치·고유명사는 출처로 확인했는가
- [ ] 금지 사항(개인 정보, 원문 통째 복사 등)을 어기지 않았는가
- [ ] 인덱스·기록 같은 후속 작업까지 끝냈는가

## 주장과 확인할 점

- "일마다 에이전트를 만들면 대부분 망한다"는 게시자의 경험담이다. 수치 근거는 없다.
- 반대 의견도 있다: 권한·도구가 크게 다른 일(예: 결제·메일 발송 vs 조사)은 에이전트를 나누는 편이 안전하다. 여기서는 "매뉴얼로 해결되는 일은 하나로, 권한이 다른 일만 나눈다"로 정리한다.
- 같은 결론을 다룬 자료: `05_LLM다루기/클로드코드/게으른빌더_가이드89편_목록.md`의 "업무를 파일·폴더로 옮기기" 항목.
