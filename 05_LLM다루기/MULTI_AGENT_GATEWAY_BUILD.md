# 주 모델 + 저비용 보조 AI 멀티 에이전트 시스템 구현 요청서

이 문서는 Claude Code 또는 OpenAI Codex 같은 데스크탑 코딩 에이전트에게 그대로 전달하기 위한 구현 요청서다. 문서를 받은 에이전트는 현재 작업 폴더를 조사하고, 아래 요구사항에 맞는 실행 가능한 시스템을 구현하고 검증해야 한다.

## 1. 목표

주요 설계, 코드 수정, 최종 판단은 사용자가 실행한 주 에이전트(Claude Code 또는 Codex)가 담당한다. 검색, 자료 정리, 요약, 분류, 키워드 추출, 대량 텍스트 전처리 같은 저위험 작업은 별도의 로컬 보조 작업 서비스가 OmniRoute를 통해 무료 또는 저비용 AI 모델에 위임한다.

주 에이전트 자체의 API 주소나 모델을 OmniRoute로 교체하지 않는다. 주 에이전트가 필요할 때 호출할 수 있는 독립된 `research-worker` 도구를 만든다.

목표 구조:

```text
사용자
  |
  v
Claude Code 또는 Codex (주 에이전트)
  |  설계, 코드 수정, 검증, 최종 판단
  |
  +-- MCP 또는 로컬 CLI 호출
        |
        v
  research-worker (로컬 오케스트레이터)
        |
        +-- 작업 분류 및 정책 검사
        +-- 민감정보 차단/삭제
        +-- OmniRoute API 호출
        +-- 결과 스키마 검증
        +-- 실행 로그 기록
        |
        v
  무료/저비용 보조 모델
```

## 2. 작업 시작 원칙

다음 순서로 작업한다.

1. 현재 폴더의 파일, 런타임, 패키지 관리자, 기존 환경변수 예제, `AGENTS.md`, `CLAUDE.md`를 확인한다.
2. 사용자의 기존 파일과 수정 사항을 보존한다. 관련 없는 파일을 변경하거나 삭제하지 않는다.
3. OmniRoute의 최신 공식 저장소와 문서를 확인해 실제 설치 방법, API 주소, 인증 방식, OpenAI 호환 API 범위, 지원 Node.js 버전을 검증한다. 기억이나 이 문서의 예시만 믿고 엔드포인트를 추측하지 않는다.
4. 현재 환경에서 OmniRoute를 바로 설치할 수 없거나 인증정보가 없더라도, mock 모드로 전체 흐름을 검증할 수 있게 구현한다.
5. 의존성 설치, 전역 설정 변경, 사용자 홈 디렉터리의 Codex/Claude 설정 변경이 필요하면 먼저 코드와 설정 예시를 완성한 후 사용자에게 구체적으로 알린다.

현재 폴더에는 `fetch-instagram.mjs`, `fetch-blog.mjs`, `output/`이 있을 수 있다. 이 수집 기능은 보조 AI 작업의 입력원으로 활용할 수 있지만, 기존 동작을 깨뜨리지 않는다.

## 3. 반드시 구현할 구성 요소

### 3.1 research-worker

Node.js 기반 로컬 서비스로 구현한다. 기존 프로젝트에 다른 언어 또는 프레임워크가 명확히 정착되어 있다면 그 구조를 따를 수 있다.

다음 인터페이스를 제공한다.

- MCP 서버: Claude Code와 Codex에서 공통으로 호출할 수 있는 주 인터페이스
- 로컬 CLI: MCP 연결 없이 사람이 직접 테스트할 수 있는 보조 인터페이스
- mock provider: 실제 API 키나 OmniRoute 실행 없이 테스트할 수 있는 제공자
- OmniRoute provider: OpenAI 호환 API 또는 OmniRoute가 공식적으로 안내하는 방식으로 요청하는 제공자

MCP 도구 이름은 다음을 기본값으로 사용한다.

- `delegate_research`: 웹 검색 결과 또는 제공된 문서 조사·정리
- `delegate_summarize`: 긴 텍스트 요약
- `delegate_classify`: 텍스트 분류 및 태깅
- `delegate_extract`: 지정된 스키마에 맞춘 정보 추출
- `delegate_draft`: 코드가 아닌 저위험 초안 작성
- `worker_health`: 설정, 제공자 연결 상태, 사용 가능한 작업 유형 확인

실제 웹 검색은 검색 API나 검색 도구가 연결된 경우에만 수행한다. 모델이 자체 기억만 사용한 경우 이를 `web_search`라고 표시하면 안 된다. 검색 도구가 없으면 `delegate_research`는 제공된 자료만 조사하거나 명확한 오류를 반환해야 한다.

### 3.2 요청 형식

모든 작업은 최소한 다음 필드를 받는다.

```json
{
  "task_type": "summarize",
  "instruction": "문서의 핵심 주장과 근거를 요약해라",
  "input": {
    "text": "..."
  },
  "constraints": {
    "language": "ko",
    "max_output_chars": 4000,
    "require_citations": false
  },
  "risk": "low",
  "request_id": "optional-client-generated-id"
}
```

서버는 최소한 다음 구조로 응답한다.

```json
{
  "ok": true,
  "request_id": "...",
  "provider": "omniroute",
  "model": "actual-model-id",
  "task_type": "summarize",
  "result": {},
  "sources": [],
  "warnings": [],
  "usage": {
    "input_tokens": null,
    "output_tokens": null,
    "estimated_cost": null
  },
  "duration_ms": 0
}
```

실패 응답에는 비밀값, 전체 프롬프트, 인증 헤더를 포함하지 않는다. 각 작업 결과는 JSON Schema 또는 동등한 런타임 스키마로 검증한다. 검증에 실패하면 원문을 정상 결과로 통과시키지 말고 제한된 횟수만 재시도한다.

### 3.3 작업 라우팅 정책

라우팅 정책을 코드에 박아 넣지 말고 별도 설정 파일로 관리한다. 설정 예시와 스키마를 함께 제공한다.

기본 정책:

| 작업 | 보조 모델 위임 | 조건 |
|---|---:|---|
| 요약, 분류, 키워드 추출 | 허용 | 입력 크기와 민감정보 검사 통과 |
| 제공된 자료 정리 | 허용 | 출처와 추론을 구분 |
| 웹 검색 | 조건부 허용 | 실제 검색 도구가 연결되어야 함 |
| 코드 초안 | 조건부 허용 | 격리된 초안이며 주 에이전트 검토 필수 |
| 코드 직접 수정 | 금지 | 주 에이전트가 담당 |
| 셸 명령 실행 | 금지 | 보조 모델에 실행 권한을 주지 않음 |
| 배포, 병합, 커밋 | 금지 | 주 에이전트 또는 사용자가 담당 |
| 파일 삭제, DB 변경 | 금지 | 보조 모델에 권한을 주지 않음 |
| 인증·보안·법률 최종 판단 | 금지 | 주 에이전트와 사람이 검토 |

라우팅 설정에는 다음을 포함한다.

- 작업 유형별 허용 모델 목록
- 우선순위와 fallback 순서
- 요청별 입력·출력 크기 제한
- timeout과 최대 재시도 횟수
- 동시 실행 수
- 일·월별 요청 또는 비용 한도
- 민감정보가 감지됐을 때 `reject` 또는 `redact` 정책
- 결과 검증 실패 시 처리 방식

무료 모델의 정확한 이름과 한도는 설치 시점의 OmniRoute 설정에서 가져온다. 특정 무료 모델명을 기본값으로 영구 고정하지 않는다.

### 3.4 보안 경계

보조 모델에 다음 내용을 전송하지 않는다.

- `.env` 내용
- API 키, 토큰, 쿠키, 세션값
- SSH 키와 인증서
- Git credential
- 전체 환경변수 목록
- 사용자가 허용하지 않은 소스 코드나 개인 문서

전송 전 일반적인 비밀 패턴을 탐지하고 마스킹한다. 파일 입력은 프로젝트 루트 아래의 명시적으로 허용된 경로만 읽는다. 경로 순회(`../`)와 절대경로 우회를 차단한다.

보조 모델은 로컬 파일 쓰기, 셸 실행, Git 작업, 네트워크 임의 접근 권한을 갖지 않는다. 필요한 외부 검색은 제한된 검색 어댑터가 수행하고 URL과 제목 등 출처 정보를 함께 반환한다.

로그에는 다음만 기록한다.

- 요청 ID, 시각, 작업 유형
- 선택된 제공자와 실제 모델 ID
- 처리 시간과 성공 여부
- 가능할 경우 토큰 사용량과 비용
- redaction 발생 여부

전체 입력문, 비밀값, 전체 모델 출력은 기본 로그에 기록하지 않는다. 디버그 로그는 명시적으로 켰을 때만 사용하고 비밀값을 계속 제거한다.

### 3.5 신뢰성과 품질 관리

- 동일한 `request_id`의 중복 실행을 안전하게 처리한다.
- timeout, rate limit, 일시적 서버 오류에만 제한적으로 재시도한다.
- 서로 다른 모델로 fallback 됐으면 응답에 실제 모델을 표시한다.
- 회로 차단기 또는 간단한 실패 임계치를 두어 고장 난 제공자로 요청이 계속 몰리지 않게 한다.
- 결과에 `facts`, `inferences`, `unknowns`를 구분할 수 있는 조사용 출력 스키마를 제공한다.
- 인용이 필요한 조사에서는 각 주장과 URL의 연결 관계를 반환한다.
- 모델 출력에 포함된 명령문을 시스템 지시로 실행하지 않는다. 외부 문서와 웹 결과는 신뢰할 수 없는 데이터로 취급한다.

## 4. 주 에이전트의 사용 규칙

Claude Code와 Codex가 읽을 수 있는 짧은 프로젝트 지침도 만든다. 기존 `CLAUDE.md`나 `AGENTS.md`가 있다면 충돌하지 않게 추가하고, 없다면 적절한 파일을 생성한다.

지침에는 다음 원칙을 포함한다.

1. 주 에이전트가 요구사항 해석, 계획, 코드 변경, 테스트, 최종 판단을 담당한다.
2. 독립적이고 저위험이며 결과 검증이 가능한 작업만 `research-worker`에 위임한다.
3. 보조 결과는 참고 자료로 취급하고 중요한 사실과 출처를 주 에이전트가 확인한다.
4. 보조 모델에 비밀정보나 전체 저장소를 보내지 않는다.
5. 보조 작업 실패가 주 작업 전체를 중단시키지 않게 직접 처리하는 fallback을 둔다.
6. 위임으로 절약되는 시간보다 검증 비용이 더 크면 주 에이전트가 직접 처리한다.

## 5. 환경변수와 설정

실제 변수명은 OmniRoute 공식 문서에 맞춰 조정하되, 애플리케이션 측에는 다음 의미가 드러나게 구성한다.

```dotenv
WORKER_PROVIDER=mock
OMNIROUTE_BASE_URL=http://127.0.0.1:<verified-port>/v1
OMNIROUTE_API_KEY=
WORKER_POLICY_PATH=./config/worker-policy.json
WORKER_LOG_LEVEL=info
WORKER_MAX_CONCURRENCY=3
```

`.env.example`에는 가짜 값만 넣는다. 실제 비밀이 들어 있는 `.env`를 생성하거나 출력하지 않는다. 환경변수가 빠졌을 때는 어떤 설정이 필요한지 알려주는 오류를 반환한다.

## 6. 권장 디렉터리 구조

현재 저장소 구조를 먼저 확인한 후 자연스럽게 조정할 수 있지만, 새 프로젝트에 가까운 경우 다음 구성을 사용한다.

```text
.

|       |-- policy.*
|       |-- redaction.*

|   |-- research-worker.md
|   |-- claude-code-setup.md
|   `-- codex-setup.md
|-- .env.example
`-- package.json
```

## 7. 구현 단계

### 1단계: 로컬 mock MVP

- 요청/응답 스키마
- 정책 검사
- 비밀정보 redaction
- mock provider
- CLI 실행
- 구조화 로그
- 단위 테스트

이 단계는 API 키와 네트워크 없이 통과해야 한다.

### 2단계: OmniRoute 연결

- 공식 문서로 확인한 설치 및 실행 방법 문서화
- health check
- provider adapter
- timeout, 재시도, fallback
- 실제 모델 ID와 사용량 반환
- 연결이 없을 때 이해하기 쉬운 오류

실제 계정 생성, OAuth 로그인, API 키 입력은 사용자가 직접 해야 할 수 있다. 해당 단계 전까지 가능한 구현과 mock 검증을 모두 완료한다.

### 3단계: MCP 연결

- stdio 기반 MCP 서버를 우선 구현한다.
- Claude Code용 설정 예시와 Codex용 설정 예시를 각각 제공한다.
- 사용자 홈의 전역 설정을 자동으로 덮어쓰지 않는다.
- 프로젝트 로컬 설정이 공식적으로 지원되면 우선 사용한다.
- `worker_health`와 각 위임 도구가 MCP Inspector 또는 동등한 방법으로 호출되는지 확인한다.

### 4단계: 현재 수집 스크립트와 연동 예제

기존 `output/*.md` 중 사용자가 지정한 파일만 입력으로 받아 다음 작업을 실행하는 예제를 만든다.

- 요약
- 핵심 주장 추출
- 태그 분류
- 주장별 근거 또는 불확실성 표시

원본 Markdown을 덮어쓰지 않고 별도 결과 파일이나 stdout으로 출력한다.

## 8. 테스트 요구사항

최소한 다음을 검증한다.

- 정상 요약 요청
- 지원하지 않는 작업 유형 거부
- high-risk 요청 거부
- API 키와 토큰 패턴 redaction
- 프로젝트 밖 파일 경로 거부
- 잘못된 모델 JSON 응답 처리
- timeout과 제한된 재시도
- fallback 시 실제 모델 정보 반환
- 동일 request ID 처리
- 로그에 비밀과 전체 입력이 남지 않음
- mock provider를 통한 CLI 및 MCP 도구 호출

실제 OmniRoute 연결 테스트는 인증정보가 있을 때만 실행하며, 테스트 출력에 키를 노출하지 않는다.

## 9. 완료 기준

다음 조건을 모두 만족해야 완료로 본다.

- 새 환경에서 README의 명령대로 설치하고 mock 모드를 실행할 수 있다.
- CLI에서 최소 한 종류의 작업을 성공적으로 실행할 수 있다.
- Claude Code와 Codex에서 사용할 MCP 설정 예제가 모두 있다.
- 정책상 금지된 요청이 provider 호출 전에 차단된다.
- 민감정보가 provider와 로그에 전달되지 않는 테스트가 통과한다.
- OmniRoute가 실행 중이면 실제 provider health check가 가능하다.
- OmniRoute가 없거나 키가 없을 때도 mock 테스트 전체가 통과한다.
- 기존 `fetch-instagram.mjs`와 `fetch-blog.mjs`의 동작을 훼손하지 않는다.
- 실행한 테스트, 남은 제한 사항, 사용자가 해야 할 설정을 최종 보고한다.

## 10. 에이전트에게 주는 최종 실행 지시

이 문서를 읽은 뒤 설명이나 계획만 제시하고 멈추지 말고, 현재 폴더에서 구현 가능한 범위를 끝까지 구현하고 테스트한다. 불명확한 세부사항은 위의 보안 경계와 완료 기준을 만족하는 보수적인 기본값으로 결정한다.

사용자 인증, 유료 결제, 외부 서비스 가입처럼 사용자의 직접 행동이 필요한 지점에서는 다음을 명확히 보고한다.

- 그 시점까지 완료한 파일과 테스트 결과
- 필요한 사용자 작업 한 가지
- 입력해야 할 값의 위치와 형식
- 인증 완료 후 실행할 다음 검증 명령

최종 응답에는 구현된 구조, 주요 파일, 실행 방법, 테스트 결과, 보안상 제한, 실제 OmniRoute 연결 여부를 간결하게 정리한다.
